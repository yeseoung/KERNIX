# KERNIX int8 양자화 설계

> 상태: 구현됨 · 작성 2026-11-11 · 대상 브랜치 `feat/model-runtime`
> 검증 절의 `test/` 파일과 테스트용 `make` 타깃은 개발 중에만 쓰고 공개 저장소에는 넣지 않았습니다. 그 절은 실행 기록입니다.

## 1. 목적

TFLite의 학습 후 양자화처럼, KERNIX 모델(`.knx`)을 int8로 줄여서 세 가지를 얻는다.

1. **추론 속도 (1순위)**: 웹캠처럼 표본을 하나씩 넣는 추론을 빠르게 한다.
2. **파일 크기**: 배포 파일을 작게 한다.
3. **실행 메모리**: 실행 중 가중치가 차지하는 메모리를 줄인다.

정확도는 float 모델과 사실상 같아야 한다. 웹캠의 확정 판정이 바뀌는 일은 1% 미만이어야 한다.

## 2. 사전 측정 (스파이크) 결과

실험 코드는 버리는 코드라 세션 임시 폴더에만 두었다. 조건은 다음과 같다.

- 장비: Apple M1
- 가중치와 입력: 수어 모델의 실제 가중치, 실제 검증 데이터와 그 중간값
- 오차 기준: float64 참조 구현

### 2.1 연산별 비교 (표본 1개 기준)

| 연산 (단어 모델) | 모양 | Accelerate float (현재) | NEON int8 `sdot` | NEON fp16 |
|---|---|---:|---:|---:|
| LSTM1 순환 `h·U` (시점마다) | 1×128 · 128×512 | 4,249 ns | **606 ns** | 3,492 ns |
| LSTM2 순환 `h·U` (시점마다) | 1×64 · 64×256 | 628 ns | **170 ns** | 831 ns |
| LSTM1 입력 투영 `x·W` (프레임마다) | 32×114 · 114×512 | **5,466 ns** | 19,443 ns | 96,864 ns |
| LSTM2 입력 투영 `x·W` (프레임마다) | 32×128 · 128×256 | **2,831 ns** | 10,486 ns | 54,401 ns |

- **행 1개짜리 연산(순환, Dense)은 int8이 3~7배 빠르다.** 단어 모델에서는 순환 연산(31번 반복)이 행렬 곱 시간의 95%를 차지한다.
- **여러 행짜리 연산(입력 투영)은 AMX float가 3.5배 빠르다.**
- **fp16은 속도 이득이 없다.** 그래서 이 설계에서 제외한다.
- **원본 입력을 그대로 int8로 바꾸면 단어 모델 첫 층의 오차가 37%다.** 입력이 픽셀 좌표(수백)와 각도(약 1)처럼 크기가 다른 특징을 섞고 있어서, 행마다 동적으로 양자화하면 작은 특징이 사라진다.

### 2.2 하이브리드 전체 실행

입력 투영은 float(AMX), 순환과 Dense는 int8로 실행했다. 검증 데이터 전체를 하나씩 넣었다.

| 모델 | 프레임당 시간 | 정확도 변화 | 예측 일치 | 웹캠 확정 판정 일치 |
|---|---|---:|---:|---:|
| 지문자 | 10.5 → 5.5 µs (1.9배) | −0.10%p | 99.00% | 99.32% |
| 단어 32프레임 (배포용) | 188 → 56 µs (3.3배) | −0.02%p | 99.93% | 99.89% |
| 단어 20개 | 59 → 20 µs (3.0배) | 0.00%p | 100% | 100% |
| 단어 어휘 | 60 → 20 µs (3.0배) | +0.02%p | 99.82% | 99.67% |

이 결과로 int8 dynamic range 방식(가중치 int8, 활성값은 호출마다 int8로 변환)을 택한다.

## 3. 목표와 제외 범위

### 목표

- `.knx` v2 형식: 가중치마다 float32 또는 int8을 고를 수 있다. v1 파일도 그대로 읽는다.
- int8 계산 커널: 표본이 적을 때 NEON `sdot`으로 계산한다.
- 내보내기 옵션: Keras와 PyTorch 내보내기에 `--quantize int8`을 추가한다.
- 기존 C API, Python 바인딩, 웹캠 스크립트를 바꾸지 않는다.

### 제외

- 완전 int8: 활성값까지 int8로 두고 층 사이에서도 int8로 전달하는 방식, 보정 데이터
- fp16
- 큰 배치용 int8 행렬 곱 커널: 큰 배치는 AMX float로 처리한다
- 수어 프로젝트 웹캠 스크립트가 int8 모델을 고르는 기능: 후속 작업으로 둔다 (§9)

## 4. 파일 형식 `.knx` v2

머리부는 `"KNX2"`와 `uint32 n_ops`다. 연산 목록과 각 연산의 필드 순서는 v1과 같고, **가중치 텐서 자리만 "가중치 블록"으로 바뀐다.** 모든 값은 리틀 엔디언이다.

### 4.1 가중치 블록

```
uint32 dtype
dtype 0 (F32)       : float32 값 rows×cols                 (v1과 같은 행 우선 배치)
dtype 1 (I8_COL)    : float32 scale[cols], int8 값 rows×cols   w[k][n] ≈ q[k][n] × scale[n]
dtype 2 (I8_ROW)    : float32 scale[rows], int8 값 rows×cols   w[k][n] ≈ q[k][n] × scale[k]
```

- `rows×cols`는 v1과 같은 in×out 방향이다. Linear는 in×out, LSTM 입력 가중치는 in×4·units, 순환 가중치는 units×4·units다.
- 양자화는 대칭 방식이다. 값은 −127~127이고 영점은 0이다. 반올림은 가장 가까운 짝수로 한다.

### 4.2 연산별 배치

- **LINEAR**: `kind, in, out, has_bias`, 가중치 블록(in×out), (has_bias면) float32 bias[out]
- **LSTM**: `kind, in, units, act, ret_seq, seq`, 입력 가중치 블록, 순환 가중치 블록, float32 bias[4·units]
- **ACT, LAYERNORM, SOFTMAX**: v1과 같다. LayerNorm의 gamma와 beta는 float32다.

### 4.3 로더 검증 (파일은 신뢰할 수 없는 입력)

v1의 검증(남은 바이트 확인, 크기 상한, 연결 일치, 끝에 남는 데이터 등)은 모두 그대로 둔다. 다음 경우에도 거부한다.

- `dtype`이 0, 1, 2가 아니다.
- scale이나 int8 값이 선언된 크기보다 짧다.
- scale이 0 이하이거나, NaN 또는 무한대다.
- int8로 계산하는 가중치(§5의 I8_COL — Linear, LSTM 순환)의 rows가 `KERNIX_INT8_MAX_K`(131,072)를 넘는다. int32 누적이 넘치지 않게 하려는 조건이다(§6.1).

거부할 때는 기존처럼 이유를 stderr에 출력하고 `NULL`을 반환한다.

## 5. 메모리 표현

| 파일의 가중치 | 메모리 표현 | 계산 |
|---|---|---|
| F32 | float32 (지금과 같음) | AMX / Accelerate |
| I8_COL — Linear 가중치, LSTM 순환 가중치 | **int8 묶음 + scale[cols]** | 행 수가 적으면 int8 `sdot`, 많으면 §6.2 |
| I8_COL — LSTM 입력 가중치 | 로드할 때 float32로 풂 | AMX |
| I8_ROW — 모든 자리 | 로드할 때 float32로 풂 | AMX |

- **int8 묶음 배치**: `sdot`이 순서대로 읽는 배치다. 출력 16개 블록 안에 k 4개 블록이 있고, 그 안에 벡터 4개(출력 4개 × k 4개)가 있다.
  - cols는 16의 배수로, rows는 16의 배수로 0을 채워 늘린다.
  - 묶음은 로드할 때 한 번만 만든다.
- **입력 가중치를 풀어 쓰는 이유**: 입력 투영은 AMX float가 더 빠르다(§2.1). 그래서 메모리에서는 float로 두고, 파일만 int8로 줄인다.
  - Keras 내보내기는 입력 투영에 I8_ROW를 쓴다. 입력 특징마다 scale을 두면 Normalization을 접어 넣어 생긴 특징별 크기 차이를 흡수할 수 있다.
  - 그 밖의 가중치는 I8_COL을 쓴다. `sdot`으로 계산하려면 출력 채널별 scale이어야 하기 때문이다.
- **기대 크기** (단어 모델 가중치): 파일은 703 KB → 약 200 KB(약 1/3.5)이고, 실행 중 가중치 메모리는 약 449 KB(1/1.57)다.

## 6. 실행

### 6.1 표본이 적을 때: int8 `sdot` 커널

```c
/* y[i][n] = (Σ_k xq[i][k]·wq[k][n]) × sx[i] × sw[n] + bias[n],  i < rows */
static inline void kernix_qmatmul(const float* x, int rows, const kernix_qweight* w, const float* bias, float* y);
```

- **입력 양자화**: 행마다 `sx = max|x| / 127`로 정하고 int8로 바꾼다(반올림, 범위 제한). 0인 행은 sx = 1로 두며 결과는 bias가 된다.
- **누적**: int32로 누적한다. 127²·K < 2³¹이어야 넘치지 않으므로 K ≤ 133,143이어야 한다. 지금 로더는 Linear 입력 크기를 `INT_MAX`까지 허용하므로, v2 로더는 int8로 계산하는 가중치의 rows(K)가 `KERNIX_INT8_MAX_K`(131,072)를 넘으면 거부한다(§4.3). LSTM은 units ≤ 4,096이라 해당하지 않는다.
- **역양자화**: 누적값을 float로 바꿔 scale을 곱하고 bias를 더한다. LSTM 순환에서는 결과를 입력 투영 값에 더한다.
- **NaN·무한대 입력**: 그 행의 출력도 NaN이 된다. float 경로와 같은 동작이며, 웹캠에서는 확정되지 않는다(교차 검증 항목).
- **적용 조건**: 행 수(LSTM은 배치, Linear는 입력 행)가 `KERNIX_INT8_MAX_ROWS` 이하일 때 쓴다. 이 값은 구현 단계에서 int8과 AMX가 같아지는 지점을 재서 정한다. 스파이크 기준으로 1행에서는 int8이 이기고 32행에서는 AMX가 이기므로, 그 사이의 값이다.

### 6.2 큰 배치: 풀어 쓴 float 사본 + AMX

- 행 수가 기준보다 많으면, 작업 버퍼를 할당할 때 int8 가중치를 float로 한 번 풀어 둔다. 이후 모든 조각과 시점이 이 사본을 쓴다.
- 이 사본은 작업 버퍼의 일부다.
  - 작업 버퍼 상한을 계산할 때 고정 크기로 먼저 뺀다. 조각 크기는 `(상한 − 고정) / 표본당 크기`다.
  - `trim()`과 재할당 때 해제한다.
- 결과적으로 float 사본은 큰 배치를 처리하는 동안에만 존재하고, 웹캠 경로는 int8만 쓴다.

### 6.3 바뀌지 않는 것

- `kernix_model_load`, `kernix_model_forward`, `kernix_model_trim`, `kernix_model_set_workspace_limit`의 시그니처와 의미
- Python `Model`
- 웹캠 스크립트

int8 `.knx`를 넘기기만 하면 int8로 동작한다.

## 7. 내보내기

- **공통 양자화 함수**: 새 파일 `test/knx_quant.py`에 둔다(지금은 `tools/knx_quant.py`). 두 내보내기 스크립트가 같이 쓴다.
  - `quantize_cols(w)`와 `quantize_rows(w)`: (scale, int8 값)을 반환한다. 모든 값이 0인 열이나 행은 scale = 1로 둔다.
  - `weight_block(w, mode)`: mode는 "f32", "i8_col", "i8_row"이며 바이트를 반환한다.
- **`test/export_keras.py`** (지금은 `tools/export_keras.py`, 비교는 `test/sign_bench.py`)
  - `--quantize int8`: 입력 투영은 I8_ROW, 순환과 Dense는 I8_COL로 내보낸다.
  - 단독 변환 명령: `python tools/convert.py 모델.h5 출력.knx [--quantize int8]`
  - `make bench-sign`은 모델마다 float와 int8을 함께 내보낸다. 그리고 정확도, 크기, 표본 1개 시간, 전체 배치 시간을 한 표에서 비교한다.
- **`test/export_mlp.py`** (지금은 `tools/export_torch.py`, 테스트 데이터는 `test/mlp_bench.py`): `--quantize int8`로 Linear를 I8_COL로 내보낸다. 정확도 테스트용 small 모델과 벤치 모델에 쓴다.
- **양자화 안 함**: 옵션이 없으면 지금처럼 v1(`KNX1`)을 내보낸다. 기존 파일과 기존 테스트는 그대로 동작한다.

## 8. 검증

### 8.1 C 자가 검증 (`test/model_test.c --check`, Metal·Accelerate 빌드 모두)

- **int8 커널 정확성**: 같은 int8 값으로 계산한 스칼라 참조 구현과 비교한다.
  - K, N이 16의 배수가 아닌 경우를 포함한다(예: K=55, N=31).
  - rows가 1부터 `KERNIX_INT8_MAX_ROWS`까지, 그리고 그보다 하나 많은 경우(AMX 경로)도 넣는다.
- **양자화 오차 상한**: 무작위 float 모델을 양자화했을 때 float 결과와의 상대 오차가 정해 둔 상한 이내인지 본다.
- **v2 로더 거부**: dtype 3, 잘린 scale, 잘린 int8 값, scale = 0 / −1 / NaN / 무한대, K가 131,073인 I8_COL Linear를 넣어 본다.
- **v1 호환**: 기존 v1 테스트가 모두 그대로 통과해야 한다.
- **기존 기능과 함께**: int8 모델에서 나눠 실행과 `trim`이 float 사본을 포함해 올바르게 동작하는지 본다. 결과는 한 번에 실행한 것과 같아야 하고, `trim` 뒤에는 작업 버퍼가 비어 있어야 한다.
- **비유한 입력**: NaN 입력 행은 NaN 출력이 되어야 한다.

### 8.2 Python·통합

- `make test-python`: int8 모델로 바인딩 출력을 확인하고, 스레드 동시 호출 검사에 int8 모델도 넣는다.
- `test/webcam_kernix_test.py`: int8 모델로 TFLite와의 교차 검증을 한다. 기준은 판정 일치 99% 이상이다.
- `make bench-sign`, `make bench-memory`: int8 행을 추가한다.

### 8.3 성공 기준 (수어 모델 7개 전부, 검증 데이터)

| 항목 | 기준 |
|---|---|
| 정확도 변화 (float 대비) | 하락 0.5%p 이하 |
| 웹캠 확정 판정 일치 (TFLite 대비) | 99% 이상 |
| 파일 크기 | float `.knx`의 1/3 이하 |

## 9. 후속 작업 (이 설계 밖)

- 수어 프로젝트의 `modules/kernix_runtime.ensure_knx`에 int8 선택지를 추가한다. 예: 환경 변수 `KERNIX_QUANT=int8`이면 `.int8.knx`로 변환해서 쓴다.
- Linear를 큰 배치에서도 int8로 계산하는 행렬 곱 커널. 측정 결과 지금은 AMX float가 더 빠르다.
- 내보내기 도구를 `test/`에서 `tools/`로 옮긴다(이전 분석 7번).
